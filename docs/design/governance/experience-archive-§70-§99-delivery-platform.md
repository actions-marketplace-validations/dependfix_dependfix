## 七十、M42 归档批次经验沉淀（测试断言真实性 / 外部工具语义 / 视觉基线连带 / 交付纪律）

> **批次**：M42 修复交付正确性 + 平台能力与体验补强（2026-10-11 归档）。以下 9 条已按 L1 / L2 / L3 三层收敛，规范落点与检查点矩阵行同步登记。

### 1. 交互断言的点击目标必须与组件事件绑定一致（e2e 弱断言与 flaky 的共同根因）

- **现象**：断言「点击表头排序」时点了表头单元格，而组件把点击绑定在单元格**内部**的按钮上 → 排序从未触发；断言却仍可能通过——接口默认按创建时间倒序返回，用例按序插入的数据使首行恰为「期望端点值」。
- **手法**：① 断言前先确认事件绑定元素（读组件模板：单元格只挂 `aria-sort`，触发器是内部按钮）；② 目标态必须**只能由目标行为产生**（用排序属性硬锁，未排序态为 `none` 必然失败）；③ 三态控件逐次点击并**等待属性回写**（异步渲染下立即读会读到旧值 → 多点击 → 状态过冲）。
- **落点**：[testing.md §6.5](../../standards/testing.md)（交互断言补充）+ 检查点矩阵行。

### 2. 与外部工具语义对齐的判定须用该工具权威实现逐形态实测

- **现象**：`.gitignore` 幂等判定的首版实现按书写直觉把「行中 `#`」当行内注释剥离，与 git 实际语义不符（git 仅把行首 `#` 当注释）→ 假命中 → 漏追加 → 报告目录可能随提交入库（**安全方向回归**）。
- **手法**：列形态清单（**含反例**）→ 用工具权威判定命令逐形态实测 → 与实现双向比对；等价类扩展倾向保守（宁可多报不可漏判）。
- **落点**：[development.md §5.1.40](../../standards/development.md)（新条款）+ 检查点矩阵行。

### 3. 改动页面的视觉基线重建含「以该页为背景」的连带面

- **现象**：页头加一个按钮 / 改 flex → 整页基线失配（预期）；**另有弹窗内浮层的视口级基线同样失配**（其取景包含该页背景）。
- **手法**：改动页面后列出该页相关的全部基线（整页 + 视口 + 元素级），逐个判断是否需重建；重建用 `--update-snapshots=all` 并连跑两遍验证幂等；无视觉守卫的页面显式登记。
- **落点**：[testing.md §6.7](../../standards/testing.md)（扩展）+ 检查点矩阵行。

### 4. 验证同进程服务时不得用同步子进程调用

- **现象**：用 `spawnSync` 拉起被测工具去验证「本进程内的拦截代理」→ 同步调用阻塞事件循环 → 代理无法 accept → 记录为空 → 误判「代理未生效」。
- **手法**：改用异步 `spawn` + 等待退出；配合**同环境反例对照**（旧配置再跑一次）证明代理确实被使用且修复确实生效。
- **落点**：[testing.md §6.10](../../standards/testing.md)（新条款）+ 检查点矩阵行。

### 5. ESM 接线断言用「部分 mock + 委托真实实现」

- **现象**：ESM 下无法用 spy 断言「A 以某实参调用 B」；整体 mock B 又会破坏依赖 B 真实行为的既有用例。
- **手法**：`vi.mock` + `importOriginal` 保留其余导出、仅包装目标函数（记录实参后**委托真实实现**）；实参容器由 `vi.hoisted` 提供，用例断言后于 `beforeEach` 清空。
- **落点**：[testing.md §6.6](../../standards/testing.md)（扩展）+ 检查点矩阵行。

### 6. 删除公共导出前必须全仓 grep（含全部测试目录）

- **现象**：删除工具函数导出时只查了源码与同目录测试，漏掉集中测试目录 → `typecheck` 报 TS2305。
- **手法**：不带路径限定的全仓检索 + 区分代码引用与文档描述性文本；测试文件按「同目录 + 集中目录」双份核对；核验引用面时注意 `rg -r` 是替换陷阱（输出被替换成假象）。
- **落点**：[development.md §5.1.39](../../standards/development.md)（新条款）+ 检查点矩阵行。

### 7. 同批同源断言必须全仓一次改净

- **现象**：同一批在多个文件写入同一 `file:line` 断言，修复时只改了其中一处 → 审计判「同源残留」。
- **手法**：修复任一处后用旧值全仓复核；跨文件同源写入是该规则的另一个变体。
- **落点**：[planning.md §4.4 第 13 条](../../standards/planning.md)（扩展）+ 检查点矩阵行扩展。

### 8. 阶段状态口径翻转的同步面含各文档速查表

- **现象**：阶段启动 / 归档时把「暂无进行中阶段」翻转为「Mxx 进行中」，漏改某文档的速查表 → 自相矛盾，且批次记录中「口径已同步」的声明失实。
- **手法**：列出全部承载位置（待办速查表 / 路线图指针 / 各文档速查表 / 首页里程碑）逐处同步。
- **落点**：[documentation.md §6](../../standards/documentation.md)（扩展）+ 检查点矩阵行。

### 9. 入口脚本（PID 1 / 子进程编排）用真实 shell + PATH 桩做脚本级测试

- **现象**：root 降权 / 子进程看护 / 信号处理等编排逻辑难被 TS 单测覆盖，但属可靠性关键路径。
- **手法**：`sh` 直驱脚本 + 经 `PATH` 注入桩命令（`id` / `sleep` / `date`）重塑环境（降权分支、即时退避、时间快进）；断言基于输出流与进程存活探测；Windows 用 `describe.skipIf` 跳过。
- **落点**：[testing.md §6.10](../../standards/testing.md)（新条款）+ 检查点矩阵行。
